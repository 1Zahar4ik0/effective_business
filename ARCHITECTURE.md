# Архитектура «Опора АПК»

## Назначение и стек
Навигатор поддержки для КФХ и сельскохозяйственных ИП Саратовской области.
Кооперативы выделены в отдельную категорию. Python/FastAPI, React/TypeScript,
PostgreSQL, Docker Compose. Сервер — модульный монолит, API и собранный интерфейс
отдаются одним приложением. Фоновый worker обслуживает события MAX.

## Пользовательский путь
MAX → анкета хозяйства → объяснимый подбор → мера и конкретный отбор →
сохранённый план документов → официальный ресурс подачи.
Переход на внешний ресурс не отправляет заявку. Локальный demo-вход и синтетические
данные доступны только в демонстрационном окружении, отдельно от production.

## Данные
Мера поддержки, версия условий и отбор — отдельные сущности. Источники,
правила, документы и дата проверки относятся к версии. У отбора собственные
сроки, часовой пояс и канал подачи. Редактор проводит draft → review → publish;
история и аудит сохраняются. Импорт создаёт черновики, не публикует автоматически.
Миграции SQL выполняются Alembic; при старте применяется upgrade head.

## Правила подбора
Декларативные правила исполняются на сервере. PASS — проверенное соответствие,
FAIL — подтверждённое несоответствие, UNKNOWN — недостаточно данных.
Жёсткое несоответствие имеет приоритет. Неизвестное не становится соответствием.
Право участия и доступность приёма оцениваются отдельно. Закрытый или
неподтверждённый отбор не показывается уверенно открытым.

publication_scope=full использует строгую редакторскую проверку полного набора условий.
publication_scope=reference публикует справочную карточку и предварительный план.
Для reference вычисляются только отдельно сверенные reference_rule_ids;
обязательная ручная проверка добавляет UNKNOWN, поэтому общий PASS невозможен.
Подтверждённые FAIL сохраняются. Применимость справочных документов — unknown.
Сейчас опубликованы 10 справочных карточек и 11 отборов; полных публикаций допуска нет.

## Сохранённые планы
План связан с владельцем и версией, сохраняет ответы, проверки, документы и маршрут.
Условия документов могут быть required, not_applicable или unknown.
Изменение анкеты и новая публикация не переписывают прежний снимок оценки.
Повторный запрос не создаёт дублирующий план; отметки документов сохраняются.

## MAX и безопасность
Подпись и возраст данных запуска проверяются сервером; ID и роль из клиента
не считаются подтверждёнными. Доступ к профилям и планам проверяется по владельцу.
Редакторские права назначаются по подтверждённому MAX ID в серверном окружении.
События MAX обрабатываются с защитой от дублей. Секреты находятся вне репозитория.
Рабочий HTTPS обслуживает nginx, PostgreSQL наружу не публикуется.

## Структура
- backend/app: API, авторизация, каталог, правила, планы, MAX и фоновые задания.
- backend/migrations и backend/tests: миграции и автоматические проверки.
- frontend: русский адаптивный интерфейс, типы API из docs/openapi.json.
- data/official: каталог, материалы проверки и официальные первоисточники.
- deploy: HTTPS, обновление сертификатов и восстановление резервных копий.
- docs: техническая документация и результаты проверок.

## Проверки и расширение
Ключевые проверки: UNKNOWN/FAIL, время приёма, неизменяемость версий, чужие планы,
повторные события MAX, миграции и сохранение данных после перезапуска.
Новый регион добавляется собственными источниками, редакциями и правилами;
условия Саратовской области автоматически не переносятся.
Фактические проверки и ограничения выпуска: docs/RELEASE-20260929-RC2.md.
Инструкция развёртывания: README.md. API: docs/openapi.json и DATA-API.yaml.
