## Откат без удаления новых данных

На VPS подготовлен /etc/opora-apk/deploy-20260928/rollback.sh, режим 0700.
Он останавливает app/worker, делает новый pg_dump текущего состояния, переключает
на opora-apk-rollback:20260927-r3, запускает с --no-build и обновляет DNS Nginx reload.
**Текущая БД остаётся на новой схеме, downgrade и восстановление старого dump не выполняются.**
Новые профили, версии, планы и assessment остаются в БД, даже если прежний UI их
полностью не отображает. Исторические исходники: /etc/opora-apk/deploy-20260928/r3-source.tar.gz.
Рабочие исходники автоматически не откатываются: до возвращения новой версии
после rollback нельзя запускать --build, иначе старый образ будет заменён новым кодом.
Старый обработчик отметок проверен чтением кода: обновляет done/revision, сохраняя
остальные ключи items; поле assessment в БД не затрагивает. Новые планы, созданные
старым кодом во время отката, будут иметь assessment=null — это допустимый старый формат.
Фактическое переключение production назад не выполнялось; совместимость чтения
проверена на копии. Если понадобится откат схемы, это отдельная задача с переносом
новых данных; нельзя подменять её заливкой предрелизной БД.

изменений. Работа продолжена существующим Docker runtime. Упаковочный скан сначала

доступные getByRole. Локальный MAX_CA_BUNDLE_HOST отсутствовал: вместо изменения
